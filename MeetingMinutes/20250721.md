    - goal_recommendation
        
        ![image.png](attachment:95e97b80-4f93-49df-8238-740fd14786b5:image.png)
        
        > 사용자의 운동 기록을 분석하여 개인화된 목표를 설정하고
        그 목표의 달성 여부에 따라 적절한 피드백(뱃지 보상)을 제공하는 자동화된 코칭 시스템
        > 
        
        1. **슬럼프 가능성 예측** (시작점) : `slump_predictor`
        
        - 사용자의 전체 운동기록을 입력받음 (`exercise_history`)
        - 기록의 패턴(주기, 완료율 변화 등)을 분석
        - 슬럼프 위험 - low, medium, high 단계 예측 (`slump_prediction`)
        
        2. **종합 분석 및 격려 메시지 생성** : `analyzer`
        
        - node 1 에서의 `slump_prediction` 와 `exercise_history` 를 함께 받아 분석
        - 평균 운동 완료율, 총 운동 횟수, 운동 기간을 계산
        - 설정된 코치 페르소나에 맞춰 AI가 개인화된 격려 메시지를 생성
        - 모든 분석 결과 및 메세지를 합쳐 `analysis_result` 로 만듦
        
        3. **AI 기반 목표 제안** : `suggester`
        
        - node 2 에서의 `analysis_result` 를 바탕으로 AI코치가 사용자에게 가장 적합하다고 판단되는 **주간목표와 월간목표**를 제안
        - JSON 데이터 형식으로 생성 → `final_goals`
        
        4. 최종 목표 **확정 및 분기점** : `finalizer`
        
        - node 3 에서 AI가 제안한 목표(`final_goals`)를 시스템의 최종 목표로 확정
        - 상태(state)에 저장
        - 이후 목표 달성 여부를 판단하는 엣지로 연결
        
        ---
        
        5. 조건부 **분기 (목표 달성 여부** 판단) : `check_goal_completion_edge`
        
        - 확정된 최종 목표(`final_goals`)와 사용자의 운동 기록(`exercise_history`)을 비교
        - 목표를 달성여부를 LLM이 엄격하게 판단
        - 목표 달성 시 (`goal_achieved`) 뱃지 생성 노드로 이동
        - 목표 미달성 시 (`goal_not_achieved`) 워크플로우 즉시 종료
        
        ---
        
        6. 개인화된 **뱃지** 생성 (보상) : `badge_generator`
        
        (목표를 달성했을 경우에만 실행) 
        
        - 달성한 주간 목표 내용을 바탕
        - AI가 사용자를 위한 재치 있고 창의적인 뱃지 이름과 설명을 생성
            
            (동기부여를 강화하는 보상 역할)
            
        
        7. **종료** : `END`
        
        '뱃지 생성'이 완료되거나, 5단계에서 '목표 미달성'으로 판단되었을 경우
        
    - exercise_recommendation
        
        ![image.png](attachment:029284da-f9b3-4735-baa1-5fb66b453dc2:image.png)
        
        > 모든 사용자 데이터를 종합적으로 이해하고
        이를 바탕으로 사용자가 아직 해보지 않은 맞춤 운동을 찾아 설득력 있는 이유와 함께 추천
        > 
        
        1. 사용자 **프로필 요약** (시작점) : `user_summarizer`
        
        1. 워크플로우가 시작되면 사용자에 대한 모든 데이터를 입력받음
            - 기본 프로필
            - 운동 기록
            - 좋아요 누른 운동
            - 저장한 루틴
            - 체형 분석 점수
        2. AI(LLM)가 전문 운동 코치 역할을 맡아 모든 정보를 종합
        3. 체형 분석 점수 해석 → 신체의 강점과 약점을 파악
        4. 사용자의 운동 선호도와 목표를 결합하여 한 문단으로 된 자연어 프로필 요약(`user_summary`) 생성
        
        2. 벡터 검색 및 필터링 **:** `vector_searcher`
        
        1. 사용자가 이미 경험했거나 좋아요를 누른 운동의 이름들을 모아 제외 목록 생성
            
            (똑같은 운동을 재추천 방지)
            
        2. node 1 에서의 `user_summary`을 검색어(Query)로 사용 → Vector DB에서 의미적으로 가장 유사한 운동들을 검색
            - 왜 자연어 프로필 요약을 검색어로 썼는가?
                
                
                | 구분 | **기존 방식 (운동 명세서 기반)** | **변경된 방식 (사용자 요약 기반)** |
                | --- | --- | --- |
                | **검색의 초점** | 운동의 속성 (키워드) | 사용자의 상황과 목표 (컨텍스트) |
                | **Query의 형태** | "초급 난이도 가슴 운동" (정형적) | "근력이 부족하고 가슴 근육을 키우고 싶은 사용자..." (서술적, 자연어) |
                | **추천의 원리** | 키워드 매칭 | 의미적 유사도 및 맥락 추론 |
                | **결과물의 질** | 검색어와 정확히 일치하는 운동을 잘 찾음 | 사용자의 숨은 니즈까지 파악하여 진정으로 개인화된 운동을 찾아줌 |
                
                단순 키워드 매칭에서 사용자의 컨텍스트(맥락)와 의도를 파악하는 '시맨틱 검색(Semantic Search)'으로 발전
                
                1. 기존 방식
                
                이전 코드에서 Vector DB를 구축하는 부분을 보면, 
                각 운동 데이터는 다음과 같은 정형화된 문장으로 변환되어 벡터로 만들어짐
                
                ```python
                f"{doc['difficulty']} 난이도의 {doc['description']} 효과를 가진 "
                f"{doc['body_part']} 부위의 {doc['category']} 운동"
                
                # 예시: "상급 난이도의 근력 향상 효과를 가진 등 부위의 웨이트 트레이닝 운동"
                ```
                
                2. 변경된 방식
                
                변경된 방식에서는 `summarize_user_node`를 통해 사용자의 모든 데이터를 종합한 개인화된 프로필 요약(`user_summary`)을 생성하고, 이것을 `query`로 사용
                
                ```python
                # 예시 query (user_summary):
                # "최근 운동을 쉬어 근력이 약해졌고, 거북목 증상이 있어 등과 코어 강화가 필요한 사용자.
                #  헬스장에서 기구 사용에 익숙하지 않아 맨몸 운동을 선호함."
                ```
                
                - 장점 1: '사용자 의도'를 검색어로 사용
                    
                    이 query는 단순 키워드가 아니라 사용자의 현재 상태, 통증, 목표, 선호도 등 복합적인 의도와 문맥을 모두 담음
                    
                - 장점 2: 시맨틱 검색 능력의 극대화
                    
                    ko-sbert-sts와 같은 최신 언어 모델은 문장의 의미적 유사도를 매우 잘 파악함
                    
                    따라서 위와 같이 서술된 사용자의 문제 상황(거북목, 약한 근력)과 Vector DB에 저장된 운동의 해결책(등/코어 강화, 스트레칭) 사이의 의미적 연결고리를 찾아내기에 적합
                    
        3. 검색된 운동 후보군 중에서 제외 목록에 포함된 운동들을 필터링
        4. 최종적으로 상위 3개의 새로운 운동(`recommendations`)을 선정
        
        3. 추천 이유 생성 **:** `reason_generator`
        
        1. node 2 에서 최종 선정된 `recommendations`과 `user_summary`을 함께 AI에게 전달
        2. AI는 친절한 코치로서, "당신은 OOO한 특성이 있으니, XXX 운동이 도움이 될 것입니다"와 같이 왜 이 운동들이 추천되었는지에 대한 설득력 있는 이유(`recommendation_reason`)를 생성
        3. 만약 2단계에서 추천할 만한 운동을 찾지 못했다면(목록이 비어있다면), 
        운동을 추천하는 대신 "지금은 새로운 것보다 하던 운동에 집중하는 게 좋겠다"는 식의 격려 메시지를 생성하여 대안을 제시
        
        4. 종료 **:** `END`
        
        추천 이유 생성이 완료되면 프로세스 종료
        
        최종 결과물인 `추천 운동 목록`, `추천 이유`가 상태(State)에 저장
        
    - main
        
        [Main_FlowChart.pdf](attachment:b3e4cf4a-9fd5-47b6-a2c0-5e5418239d43:Main_FlowChart.pdf)
        
        사용자의 자세 사진을 받아 최종 결과를 생성하는 AI 피트니스 코치 시스템
        **분석 -> 진단 -> 운동 추천 -> 영상 검색 -> 영상 검증 -> 추가 정보(댓글) 제공**
        
        ### 1. 자세 분석 및 진단 (`analyze_user_pose_node`) - 시작
        
        사용자가 제공한 이미지 한 장과 분석 모드(`front` 또는 `side`)를 입력받아 워크플로우 시작
        
        - **프로세스:**
            1. `PostureAnalyzer`가 YOLO 모델을 사용해 이미지에서 사용자의 주요 관절 키포인트를 감지
            2. 감지된 키포인트를 바탕으로 어깨 기울기, 거북목 각도 등 수치적인 자세 분석을 수행
            3. 분석된 수치 데이터와 피드백을 Ollama LLM(`llama3.2`)에 전달 → 사용자가 이해하기 쉬운 자연어 진단 메시지를 생성
        - **결과:**
            
            분석된 **키포인트 데이터**, **수치 점수**, 그리고 **자연어 진단 결과**(`diagnosis`)를 상태(state)에 저장
            
            "두 사진 분석 완료" 메시지를 슈퍼바이저에게 보고합니다.
            
        
        ### 2. 평균 점수 레이더 차트 생성 (`plot_avg_radar_chart_node`)
        
        - **시작:** 슈퍼바이저가 "두 사진 분석 완료" 보고를 받고 노드 호출
        - **프로세스:**
            1. 이전 단계에서 얻은 `diagnosis`에서 부위별 점수(목, 어깨, 골반, 척추 등)를 추출
            2. 각 부위별로 평균 점수 계산
            3. `data_server.py`에 정의된 `plot_radar_chart` 함수를 직접 호출
            → 평균 점수들을 기반으로 시각적인 레이더 차트 이미지를 생성하고 파일로 저장
            4. 평균 점수가 가장 낮은 부위가 어디인지 식별하여 `lowest_score_part`로 상태에 저장
        - **결과:**
            
            생성된 레이더 차트 이미지의 경로(`radar_chart_path`)와 가장 취약한 부위 이름(`lowest_score_part`)을 상태에 추가
            
            "평균 레이더 차트 생성 완료" 메시지를 슈퍼바이저에게 보고
            
        
        ### 3. 맞춤 운동 추천 (`recommend_exercise_node`)
        
        - **시작:** 슈퍼바이저가 "평균 레이더 차트 생성 완료" 보고를 받고 이 노드를 호출합니다.
        - **프로세스:**
            1. 이전 단계에서 생성된 자연어 진단 결과(`diagnosis`)를 가져옵니다.
            2. LLM(`gpt-4o-mini`)을 이용해 이 진단 내용에 가장 적합한 운동을 찾기 위한 검색어(Query)를 특정 형식에 맞게 생성합니다. 
            (예: `중급 난이도의 유연성 향상 효과를 가진 골반 부위의 스트레칭 운동`)
            3. 생성된 검색어로 Vector DB를 조회하여, 의미적으로 가장 유사한 운동 단 한 개를 찾아냅니다.
        - **결과:**
            
            DB에서 찾은 **추천 운동 정보**(`recommended_exercise`)를 상태에 저장
            
            "DB 기반 운동 추천 완료" 메시지를 슈퍼바이저에게 보고
            
        
        ### 4. 사용자 선택에 따른 분기 (AI 코치 vs 영상 추천)
        
        - **시작:** 슈퍼바이저가 "운동 추천 완료" 보고를 받으면, **프로그램이 잠시 멈추고 사용자에게 입력을 요구합니다.**
        - **프로세스:**
            - `1` 입력: 슈퍼바이저는 다음 작업으로 `ai_coach_interaction` 지정
            - `2` 입력: 슈퍼바이저는 `video_search` 지정
            - 잘못된 입력 시: 기본값인 `video_search`로 지정
        
        ### 5-A. AI 코치와 대화 (`ai_coach_interaction_node`)
        
        - **시작:** (사용자가 `1`을 선택했을 경우) 진단 내용과 추천 운동 정보를 바탕으로 대화 시작
        - **프로세스:** LLM이 사용자의 진단 결과와 추천 운동을 바탕으로 자세 교정의 중요성을 설명하고 동기를 부여하는 격려 메시지를 생성합니다.
        - **결과:**
            
            "AI 코치 대화 완료" 메시지를 슈퍼바이저에게 보고
            
            이 보고를 받은 슈퍼바이저는 곧바로 **최종 결과 생성(`present_final_result`)** 단계로 연결
            
        
        ### 5-B. 보충 영상 검색 (`video_search_node`)
        
        - **시작:** (사용자가 `2`를 선택했거나, 이후 단계에서 영상 재검색이 필요할 경우) 노드가 실행
        - **프로세스:**
            1. 2단계에서 추천된 **운동 이름**을 기반으로 유튜브 검색어 생성 (예: `라운드 숄더 스트레칭`)
            2. `ChatbotActionNode`가 유튜브 API를 호출하여 **자막이 있는 영상**을 검색합니다.
            3. **재검색**의 경우, 이전에 실패했던 영상 URL(`tried_video_urls`)은 **결과에서 제외**하여 새로운 영상 검색 시도
        - **결과:**
            
            찾은 영상의 **URL**과 **검색어**(`chatbot_result`)를 상태에 저장
            
            "유튜브 영상 검색 완료" 메시지를 슈퍼바이저에게 보고
            
            재검색 횟수(`search_retries`) 1 증가
            
        
        ### 6. 영상 요약 (`summarize_video_node`)
        
        - **시작:** 슈퍼바이저가 영상 검색 완료 보고를 받고 이 노드를 호출합니다.
        - **프로세스:**
            1. 이전 단계에서 찾은 유튜브 영상 URL을 `youtube_summary_agent`에 전달합니다.
            2. `youtube_summary_agent`는 내부적으로 **스크립트(자막)를 추출**하고, LLM을 통해 **스크립트를 구조화된 JSON 형태로 요약**합니다.
            3. 영상에 달린 **댓글의 총개수**(`comment_count`)도 함께 가져옵니다.
        - **결과:**
            
            **영상 요약 정보**(`youtube_summary`)와 **댓글 수**(`comment_count`)를 상태에 저장
            
            "영상 요약 완료" 메시지를 슈퍼바이저에게 보고
            
        
        ### 7. 영상 요약 내용 검증 (`validate_summary_node`)
        
        - **시작:** 슈퍼바이저가 영상 요약 완료 보고를 받고 이 노드를 호출합니다.
        - **프로세스:**
            1. LLM에게 **사용자의 최초 진단 내용, 추천 운동, 영상 요약본**을 모두 제공합니다.
            2. "이 영상이 사용자의 문제를 해결하는 데 정말 관련이 있는가?"를 **`is_relevant` (true/false)** 값으로 판단
            특정 스포츠(축구, 야구 등) 기술 훈련 영상은 관련 없음으로 처리
        - **결과:**
            - **검증 성공:** "요약 검증 성공" 메시지를 슈퍼바이저에게 보고
            - **검증 실패:** "요약 검증 실패" 메시지를 슈퍼바이저에게 보고
        
        ### 8. 슈퍼바이저의 2차 결정 (검증 결과에 따른 분기)
        
        - **검증 성공:** 슈퍼바이저는 5단계에서 가져온 댓글 수(`comment_count`)를 확인
            - 댓글이 **10개 이상**: `ask_user_response` 노드 호출
            - 댓글이 **10개 미만**이면: `comment_summary_unavailable` 노드 호출
        - **검증 실패:** 슈퍼바이저가 재검색 횟수(`search_retries`) 확인
            - 재검색 횟수가 **2회 미만**: 4-B 단계(`video_search`)로 되돌아가 재검색 지시
            - 재검색 횟수가 **2회 이상**: `present_final_result` 노드를 호출
        
        ### 9. 사용자에게 추가 정보(댓글 요약) 의사 확인
        
        - **`ask_user_response_node`:** (검증 성공 & 댓글 10개 이상일 때) 사용자에게 "댓글 반응도 요약해 드릴까요?"라고 묻고 입력을 받습니다.
        - **`comment_summary_unavailable_node`:** (검증 성공 & 댓글 10개 미만일 때) "댓글 수가 적어 요약을 제공하지 않습니다"라는 메시지를 상태에 기록하고 슈퍼바이저에게 보고
        이후 바로 최종 결과 단계로 연결
        - **`rerun_youtube_agent_node`:** (사용자가 '네'라고 긍정적으로 답했을 때) `youtube_agent`를 다시 실행하여 이번에는 댓글을 수집하고 요약하여 상태에 저장합니다.
        
        ### 10. 최종 결과 생성 및 종료 (`present_final_result_node`, `END`)
        
        - **시작:** 이전 경로(AI코치 대화 종료, 영상 재검색 최종 실패, 댓글 요약 완료/거절 등)로부터 호출
        - **프로세스:** 지금까지 상태(state)에 누적된 모든 데이터를 종합하여 최종 JSON 결과물 생성
        (진단 결과, 추천 운동, 영상 정보 및 요약 등)
        - **종료:** 워크플로우 완전히 종료(`END`)
